# Архитектура и границы

`BunarClient` только регистрирует renderer и keybinding. `ClickGuiScreen`
выполняет hit testing и извлекает состояние, не вызывает OpenGL.
`BunarRenderState` содержит значения, а не callback с захваченным mutable Screen.
`PanelLayout` используется и при кликах, и при рисовании: resize и GUI scale
не требуют отдельной системы координат.

`BunarGuiRenderer` владеет GL-ресурсами до закрытия renderer Minecraft.
Ресурсы создаются лениво при наличии текущего GL-контекста. `RectBatch`
не переставляет элементы по цвету, чтобы сохранить альфу и painter order.
Буфер ограничен: на переполнении выполняется flush. Text — отдельный проход
NanoVG после геометрии; для будущего текста между слоями потребуется явный flush.

`SeparableBlur` читает основную цветовую текстуру Minecraft, а пишет в отдельный
PIP target. Ping-pong textures исключают feedback loop. Разрешение targets —
половина target viewport с минимумом 1×1. Выполняются горизонтальный, вертикальный
проходы и финальный composite. OpenGL только на render thread.
Фон размыт на весь экран, затем затемнён; blur отдельной области пока не реализован.

`RenderPreparation` — один daemon worker и один cached future. Нет заданий каждый
кадр и накопления очереди. Сейчас он готовит только маленький kernel; вынос такой
работы не является доказательством ускорения. Будущую подготовку геометрии можно
добавлять через bounded latest-frame exchange с immutable snapshot.

Следующий этап: отдельный реестр модулей с типизированными настройками и отдельная
модель HUD layout. Модули не должны владеть GL-контекстом; они передают данные
renderer. Пока эти абстракции не нужны и не добавлены пустыми классами.
